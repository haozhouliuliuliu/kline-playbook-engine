## Logical identity flow (now end-to-end)

```text
ReplayStepBinding (actual governed wake: logical + runtime identity)
  -> preflight smoke-wakes blueprint (logical_wake_selection_identity,
     wake_identity, close_time per call_1/2/3)
  -> future V0_2 two-identity machine authority (sealed pairs)
  -> runtime exact comparison: pre-call guard per wake AND post-drive
     _verify_smoke_wake_bindings (both identities, independent checks)
  -> PASS evidence (per-call both identities) / fail-closed evidence
     (admitted_wakes retain both identities)
```

The preflight logical identity is sourced directly from the actual `ReplayStepBinding` generated by the current replay path; it is not recomputed through a second independent formula.

## Fail-closed binding semantics

For each exact call (`call_1`, `call_2`, `call_3`) the runner fails closed before that wake's provider call (via the pre-call guard) and again after the drive (via `_verify_smoke_wake_bindings`) if either:

- actual `logical_wake_selection_identity !=` authority logical identity; OR
- actual runtime `wake_identity !=` authority runtime wake identity.

These are independent checks: a correct runtime identity never masks a bad logical identity, and a correct logical identity never masks a bad runtime identity. No retry, fallback or replacement-wake behavior was added; a call 4 remains impossible by construction.
