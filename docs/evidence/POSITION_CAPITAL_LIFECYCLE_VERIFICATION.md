# 持仓与资金生命周期可行性验证

日期：2026-08-15

工具结论：`USE_EXISTING`。实现只使用 Python 标准库和项目已有模块，没有新增外部框架、交易连接或依赖。

## 已证明

- `ChronologicalValidationRunner` 中的有效 `FILLED` 结果会按请求、品种、数量、成交价、执行假设身份和资金假设身份生成确定性持仓；无成交或初始伪造持仓会被拒绝。
- `CapitalSnapshot` 与各类转换均为不可变对象，记录持仓数量、开仓均价、保证金、现金、已实现/未实现盈亏、合成成本、权益、可用资源、状态时点及身份引用。
- `MarkObservation` 必须绑定当前持仓并在持仓状态之后独立观察和可用；截止时点之后、错误品种、错误请求或错误持仓的盯市会失败关闭。
- 合成维持保证金率、违约规则和强平规则版本进入 `CapitalMarginAssumptions.identity_id`；任何结果相关改动都会改变身份。
- 健康权益不会产生强平。权益低于合成维持保证金要求时，会先留下违约证据，再生成确定性强平要求。
- 强平只接受违约之后独立可用且可交易的现有 `ExecutionObservation`；缺失、截止后可用或不可交易的观察只产生确定性未成交结果，不会伪造成交。
- 强平成交按既有合成滑点与费用结算，只实现一次盈亏、只释放一次保证金，并关闭最小单持仓夹具。
- 所有事实继续写入同一个 `EvidenceLedger`，绑定既有 `ExperimentIdentity`、执行/资金假设身份、盯市引用和持仓/强平事实引用；`FINAL_UNSEEN` 仍在生命周期运行前默认拒绝。
- 相同输入历史会得到完全相同的快照、转换、强平结果和证据身份。
