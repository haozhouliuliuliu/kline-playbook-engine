# 中国期货合约生命周期与执行语义可行性验证

日期：2026-08-16

工具结论：`USE_EXISTING`。本包只使用 Python 标准库和项目已有模块，没有新增外部交易、行情、回测或经纪商依赖。

## 已实现并验证

- 新增不可变、版本化的合约目录，显式记录交易所、品种族、具体合约、上市与停用边界、乘数、最小变动价位、币种与单位、涨跌停规则身份、平今/平昨成本元数据身份和合约元数据版本；所有影响结果的字段均进入确定性身份哈希。
- 连续或主力符号仅作为研究映射抽象。订单在决策时点必须通过显式映射计划唯一解析到已上市且未停用的具体合约；映射缺失、歧义、尚不可用或目标不在合约目录时失败关闭。
- 映射条目带有效时间、截止时间、可用时间和版本身份。未来换月信息不能改写更早的解析、成交、持仓或证据。
- 映射从 A 切换到 B 不会把已有 A 持仓改成 B；A 必须先显式平仓或被有效强平，之后开 B 会形成独立的执行和持仓事实。
- 执行观察与强平观察必须绑定具体合约。观察价格、滑点后价格和涨跌停边界使用 `Decimal` 精确校验最小变动价位，不进行静默舍入。
- 合约需要涨跌停元数据时，只使用执行时点已可见且身份、交易日和规则一致的唯一事实。区间外、封板或显式不可交易观察产生确定性未成交；缺失或歧义事实失败关闭。
- 持仓快照区分今仓和上一交易日仓。交易日切换复用 `SessionMetadata` 的交易日权威，包括夜盘归属；`CLOSE_TODAY` 与 `CLOSE_PREVIOUS` 不可跨桶替代，通用 `CLOSE` 只按版本化的合成规则确定性解析。
- 平今与平昨的合成成本规则不可变且有独立身份；成本结果、平仓偏移、涨跌停事实、合约目录、映射计划和映射条目身份进入现有执行结果与 `EvidenceLedger`。
- 继续复用 `CompletedBar`、点时可见性、`ChronologicalValidationRunner`、执行/资金/持仓生命周期、`StrategyIdentity`、`ExperimentIdentity`、`EvidenceLedger` 和 `FinalUnseenFirewall`，没有创建第二套状态、账本或执行系统。
- 相同合约、映射、行情和订单历史产生相同解析、执行、持仓和证据身份；`FINAL_UNSEEN` 仍在合约解析前默认拒绝。
