# 多策略交互与组合冲突语义可行性验证

日期：2026-08-16

工具结论：`USE_EXISTING`。本包只使用 Python 标准库和项目已有模块，没有新增交易、组合优化、插件、技能或代理框架依赖。

## 已实现并验证

- `PortfolioEvaluationIdentity` 绑定排序后的策略/实验成员身份、冲突政策身份、共享资金政策身份，以及现有数据类别、合约目录、点时映射、交易时段、涨跌停事实、执行、资金和偏移成本身份。成员输入顺序不改变身份，重复成员或策略/实验不一致失败关闭，政策版本变化会改变身份。
- 每个 `PortfolioCandidate` 显式保留策略、实验、请求、决策时点、研究符号、订单动作、方向、数量、执行观察和执行/资金假设身份；请求或归属不一致失败关闭，没有匿名组合订单。
- 冲突检测前复用 `ContractResolver` 将研究符号按决策时点解析为具体合约。不同研究符号映射到同一具体合约时能够发生冲突；缺失、歧义或不一致映射沿用既有失败关闭语义。
- 合成冲突政策固定为：相同决策时点按“策略身份、请求身份”排序；同一具体合约的相反开仓方向由排序第一项的方向获胜，同方向候选分别保留；重复请求使整次评估失败。候选容器顺序不会决定胜负。
- 冲突落败者在执行前被拒绝，不会进入成交或资金变化。同方向候选分别通过现有 `ChronologicalValidationRunner`、合约、涨跌停和资金路径，不合并为匿名订单。
- 共享资金政策固定为：按仲裁后的确定性顺序使用同一可用资金状态；先成交的保证金和成本立即减少后续可用资金。单独可负担的两个策略可因共同资金不足而使后者得到确定性 `INSUFFICIENT_MARGIN`，未成交或冲突拒绝不消费资源。
- `PositionDirection` 已进入既有订单和持仓快照；多头/空头开平仓、盯市和强平使用相反的买卖侧滑点与盈亏符号，不在组合层复制执行计算。
- 每个策略袖套保留具体合约、方向、数量、保证金、成本、已实现/未实现结果及执行/资金假设身份。袖套拒绝接收其他策略的持仓，组合总保证金、成本和盈亏必须与全部袖套精确对账。
- 对账还验证：请求不重复、冲突拒绝者不成交、每个成交恰有一个策略归属持仓、没有未成交持仓事实。只有防火墙、点时解析、仲裁、共享资金、既有执行路径和对账全部完成后，才写入成员级 `PORTFOLIO_CONFIRMED` 事实。
- 全部事实继续写入现有 `EvidenceLedger`，绑定成员实验、组合身份、冲突与共享资金政策、候选/冲突/成交/持仓及对账事实。单策略运行的确认记录在组合对账前被延后，避免产生过早的确认事实。
- 每个成员先经现有 `FinalUnseenFirewall`。`FINAL_UNSEEN` 对全部成员留下拒绝事实后停止，不解析合约、不仲裁、不执行，也不能通过新组合身份清洗暴露历史；`FAST` 仍不能产生组合确认。

## 明确的合成假设

- 同时候选排序：`STRATEGY_ID_THEN_REQUEST_ID`。
- 相反开仓方向：`FIRST_DIRECTION_WINS`，并保留获胜方向的全部同向候选。
- 同向处理：`ALLOW_SEPARATE`。
- 共享资金：`SEQUENTIAL_AVAILABLE_CAPITAL`，消费保证金与合成成本。
- 归属：`SEPARATE_SLEEVES`。
- 最小组合协调路径仅接受开仓候选；策略袖套内的跨候选平仓、生产经纪商净额和永久风险规则没有被臆造。
